# Chrome 웹스토어 제출 초안

[English](STORE-LISTING.md) · [README](../README-KR.md)

등록용 소개문과 체크리스트입니다. 등록 완료나 승인 결과가 아닙니다. 네이티브 설치·실제 GitHub 검증은 [QA](QA-KR.md)의 미완료 항목입니다.

## 이름

RepoDelta

## 짧은 설명

마지막으로 직접 확인한 시점 이후의 GitHub 변경점을 확인하세요. 로컬 기준점과 읽기 전용 커밋·파일 비교를 제공합니다.

## 상세 설명

지난번에 읽던 곳부터. RepoDelta는 GitHub 저장소에 작은 Delta 버튼을 추가하고, 기본 브랜치를 마지막으로 확인한 정확한 커밋과 비교합니다.

첫 기준점을 저장한 뒤 다시 방문하면 그동안 달라진 커밋과 파일을 확인할 수 있습니다. 페이지를 열었다는 이유만으로 변경점을 읽음 처리하지 않습니다. 확인 완료를 누르면 읽는 도중 새로 올라온 커밋이 아니라 이미 화면에 표시된 버전까지만 기록합니다.

주요 기능:
- 기본 브랜치의 명시적인 로컬 확인 기준점.
- 커밋·변경 파일, 추가·수정·삭제·이름 변경, 줄 수 및 필터.
- 해당 버전에 고정된 파일 링크와 GitHub 비교 화면 연결.
- 브랜치·이력 변경과 비교 불가를 구분하는 경고.
- 오래된 탭이 최신 기준점을 덮어쓰지 못하도록 보호.
- EN/KR, GitHub 테마, 키보드 조작.
- 로컬 JSON 백업과 선택적 세션 전용 GitHub 토큰.

공개 저장소는 GitHub 비인증 API 한도 안에서 조회합니다. 비공개 저장소는 필요한 저장소만 선택하고 Contents 읽기 권한을 가진 fine-grained 토큰을 사용합니다. 토큰은 확장 세션에만 보관하며 백업에는 넣지 않습니다.

GitHub 쓰기, 데이터 판매, 이용 분석, 개발자 운영 서버 연결은 없습니다. 다만 조회한 저장소 자료를 얻기 위해 GitHub API와 통신합니다. GitHub나 Google의 공식 제품이 아닙니다.

범위: 기본 브랜치만 지원하며 파일별 읽음 상태는 없습니다. 한 비교에서 커밋 최대 500개를 표시하고, GitHub API의 파일 목록 제한 가능성은 별도 안내합니다. 정기 폴링, 브라우저 종료 중 감시, 전체 인라인 diff는 제공하지 않습니다. 기준점은 해당 브라우저에 저장하며 설치 전의 방문 이력은 복원하지 않습니다.

## 권한 사유

| 권한 | 목적 |
| --- | --- |
| `storage` | 기준점·설정 및 세션 토큰·API 캐시 보관 |
| `https://github.com/*` | 현재 저장소 식별과 버튼·패널 표시 |
| `https://api.github.com/*` | 저장소 메타데이터·기본 브랜치 HEAD·커밋 비교 읽기 |

단일 목적은 명시적으로 확인한 버전 이후 기본 브랜치의 변경점을 검토하는 것입니다. 원격 실행 코드·외부 백엔드·전체 사이트 권한·방문 기록·쿠키·광고·분석 수집·GitHub 쓰기 기능을 포함하지 않습니다.

## 데이터 이용 신고 주의

모든 항목을 기계적으로 ‘수집하지 않음’으로 처리하지 마세요. 개발자 서버로 보내지 않더라도 확장은 GitHub의 현재 저장소·URL, 커밋·파일 경로, 선택적 인증 토큰을 처리합니다. 실제 데이터 흐름에 현행 웹스토어 신고 정의를 적용해야 합니다. 토큰은 인증 정보이고 비공개 저장소 이름은 민감할 수 있습니다. 행동 분석·판매·무관한 이용은 하지 않습니다. GitHub API 전송과 로컬·세션 저장 설명을 신고서와 개인정보 처리방침에 일치시킵니다.

## 제출 전

- [QA](QA-KR.md)의 실제 브라우저·GitHub 점검을 모두 완료합니다.
- 최종 Chrome ZIP의 루트에 `manifest.json`이 있고 직접 설치 시 오류가 없는지 확인합니다.
- `public/privacy-policy.html`과 CSS·아이콘을 실제 공개 HTTPS 주소에 호스팅합니다. 제공된 파일은 아직 호스팅된 정책이 아닙니다.
- 실제로 확인하는 개발자 문의 경로를 등록합니다. 프로필 링크가 적절한지 확인하고 필요하면 별도 지원 페이지로 바꿉니다.
- 실제 GitHub에서 토큰·비공개 자료 없는 화면을 새로 캡처합니다. 제공된 테스트 화면은 실제 연동 성공의 증거가 아닙니다.
- 이름 중복·소개문 길이·현행 권한·데이터 이용 정책·최소 브라우저 동작을 확인합니다.
- 소스 ZIP이 아닌 설치용 ZIP을 업로드합니다. 개발용 모의 데이터·테스트·소스 문서는 제출 패키지에서 제외합니다.
- 승인 후 실제 스토어 설치 URL을 확인해 README 등에 추가합니다. 이 패키지에는 가상의 주소를 넣지 않았습니다.

참고: [개발자 정책](https://developer.chrome.com/docs/webstore/program-policies) · [사용자 데이터 FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq) · [MV3 원격 코드](https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code).

새 Chrome ZIP과 `public/icons/128.png`를 사용합니다. 갱신한 스크린샷은 `docs/screenshots`에 있습니다. 스크린샷은 모의 저장소 데이터이며 실제 GitHub 연동 검증 화면으로 표시하면 안 됩니다. 웹스토어 관리 화면에 따로 올린 아이콘·소개 이미지는 저장소 수정만으로 바뀌지 않으므로 별도 갱신해야 합니다.
