# RepoDelta 아키텍처

[English](ARCHITECTURE.md) · [README](../README-KR.md)

## 범위와 구성

RepoDelta 1.0.3은 github.com 저장소의 기본 브랜치에 대한 확인 기준점을 명시적으로 저장하는 읽기 전용 Chrome Manifest V3 확장입니다. 백엔드, GitHub 쓰기, 이용 분석, AI 연동, 런타임 패키지 의존성이 없습니다. JavaScript는 `globalThis.RepoDelta` 네임스페이스 아래 로컬 파일로 분리했습니다. 서비스 워커는 패키지 내부 `importScripts`, 콘텐츠 스크립트는 매니페스트의 명시적 목록으로 로드합니다. Node.js 22 내장 모듈로 검사·테스트·복사·ZIP 패키징을 수행합니다.

```text
GitHub 페이지 / 도구 모음 팝업 / 설정
  -> 구조 검증한 런타임 메시지
  -> 발신자·작업 허용 목록 검증
  -> DeltaService
     -> Store: 신뢰 컨텍스트 한정 저장, 직렬 쓰기
     -> GitHubClient: 허용한 읽기 전용 API
  <- 제한·정규화한 조회 스냅샷 또는 오류
```

콘텐츠 스크립트에 토큰이나 전체 저장소 목록을 전달하지 않습니다. `BOOT`는 현재 저장소의 로컬 상태만 읽고 API를 호출하지 않습니다. `CHECK`는 저장소 메타데이터, 기본 브랜치 HEAD, 필요한 경우 고정 SHA 비교를 조회합니다. 토큰·백업·전체 관리 작업은 설정 페이지로 제한합니다. 언어 변경에는 범위가 좁은 별도 메시지를 사용합니다. 서비스 워커는 발신 확장 ID와 저장소 문맥을 검증하며 임의 URL을 대신 요청하는 프록시가 아닙니다.

## 기준점 저장의 일관성

기준점은 소유자·저장소 이름, 숫자 ID, 기본 브랜치, 전체 SHA, 시각, 임의 revision을 가집니다. `CHECK`가 기준점 revision·화면의 HEAD·인증 epoch를 묶은 스냅샷을 워커에서 생성합니다. `MARK`는 사용자가 임의로 제출한 SHA가 아닌 스냅샷 ID를 받습니다. 유효기간과 기존 revision을 검증한 뒤 직렬화한 변경 작업으로 표시된 SHA를 기록합니다.

확인 완료 중 최신 HEAD를 재조회하지 않습니다. 여러 탭이 같은 이전 revision으로 동시에 쓰면 하나만 성공합니다. 파일 필터나 아직 펼치지 않은 커밋은 개별 읽음 상태가 아니므로 확인 창에서 전체 버전 기준임을 알립니다. 페이지 열기만으로 기준점을 만들거나 전진시키지 않습니다.

## 상태 구분

| 관찰 결과 | 처리 |
| --- | --- |
| 기준점 없음 | 현재 HEAD와 명시적인 추적 시작 |
| 빈 저장소 | 저장할 HEAD가 없어 기준점 저장 불가 |
| 같은 SHA | 새 변경 없음 |
| 예상 기준점 관계에서 앞으로 진행 | 일반 변경점 |
| 뒤로 이동·분기·예상과 다른 공통 조상 | 이력 변경 경고 |
| 기본 브랜치 이름 변경 | 브랜치 변경 경고 |
| 같은 경로의 숫자 저장소 ID 변경 | 저장소 식별 변경 경고 |
| 메타데이터·HEAD는 읽히지만 비교 404/409/422 | 원인을 단정하지 않는 비교 불가 |
| 인증·권한·한도·네트워크·서버 오류 | 이력 변경으로 오인하지 않고 오류 표시 |

강제 푸시, 리베이스, 브랜치 되돌리기는 결과 관계만으로 원인을 확정할 수 없어 관찰된 관계를 안내합니다. 비정상 상태에서 기준점 재설정은 별도 확인을 거칩니다. 저장소 이름·소유자 변경은 자동 이관하지 않으며 현재 정식 URL에서 새 경로를 등록해야 할 수 있습니다.

## API·페이지 처리

다음 요청 형태만 허용합니다.

```text
GET /repos/{owner}/{repo}
GET /repos/{owner}/{repo}/commits?sha={defaultBranch}&per_page=1
GET /repos/{owner}/{repo}/compare/{baseSHA}...{headSHA}?per_page=100&page={1..5}
```

`credentials: omit`, JSON Accept, API 버전 `2022-11-28`을 사용합니다. 패키지 작성 시 지원되는 안정 버전이며 공식 지원 종료 예정일은 2028-03-10입니다. 후속 배포 시 다시 확인해야 합니다. 요청 직렬화·중복 병합·5분 캐시·ETag 재검증·18초 제한 시간을 적용합니다. 수동 새로고침은 캐시 신선도만 우회하고 API 재시도 제한은 우회하지 않습니다. 자동 무한 재시도는 없습니다.

커밋은 오래된 순으로 100개씩 최대 500개까지 명시적으로 더 불러옵니다. 파일 목록은 첫 비교 페이지에서 유지합니다. GitHub API는 전체 비교에 최대 300개 파일을 반환하므로 정확히 300개가 왔더라도 전체 목록이라고 단정하지 않습니다. 패치는 저장하지 않고 상세 diff는 GitHub에서 엽니다. 파일 링크는 검증한 SHA와 이스케이프한 경로로 만들며 삭제 파일은 이전 기준점으로 연결합니다.

임의 도메인으로 리디렉션하며 토큰을 전송하지 않습니다. 브라우저가 리디렉션 정보를 차단하면 현재 정식 URL로 다시 방문하도록 별도 오류를 냅니다. 토큰 변경 시 진행 중 요청을 취소하고 캐시·스냅샷을 무효화합니다. 인증 epoch가 바뀐 결과는 저장하거나 반환하지 않습니다.

## 저장·백업·보안

`storage.local`에는 환경 설정과 최대 1,000개의 기준점을 유지합니다. `storage.session`에는 선택적 토큰, 인증 epoch, API 캐시, 한도, 조회 스냅샷을 둡니다. 두 저장소 모두 `TRUSTED_CONTEXTS`로 제한합니다. 세션 정보는 브라우저 재시작·확장 재로드 등에 따라 사라지지만 네이티브 환경의 유지 동작은 이번 작업에서 직접 검증하지 못했습니다.

API 캐시는 40개 항목과 JSON 크기 목표치로 정리합니다. 스냅샷은 사용 시 30분 만료를 검사하며 개수 16개 및 크기 목표치에 따라 오래된 것을 제거합니다. 가장 최근 스냅샷 하나는 크기 목표를 초과해도 유지하되 문자열·행 수 정규화로 데이터량을 제한합니다. 실제 저장소 할당량 초과는 성공으로 처리하지 않고 오류를 반환합니다. 주기적인 만료 삭제 타이머는 없습니다.

가져오기는 최대 1 MiB JSON, 최대 1,000행을 전체 검증한 다음 기존 항목을 덮어쓰지 않고 병합합니다. 내보내기는 허용한 기준점 정보만 포함하고 토큰·API 캐시·커밋 메시지·내부 revision을 제외합니다. 비공개 저장소 이름이 포함된 백업은 민감할 수 있습니다. 로컬 저장소를 암호화 금고로 표현하지 않습니다.

## 화면·페이지 이동

현재 URL과 일치하는 저장소 메타데이터를 우선 확인하고 GitHub 버튼 옆에 독립 컨트롤을 놓습니다. 목록에는 `li` 래퍼를 쓰되 Shadow DOM은 그 안의 `span`에 붙입니다. 알려진 저장소 페이지에서 헤더를 찾지 못하면 플로팅 버튼을 사용합니다. 소프트 탐색 이벤트·디바운스한 MutationObserver·가시성 이벤트로 경로를 재평가하고 이전 페이지의 비동기 응답은 폐기합니다.

네이티브 모달의 배경 비활성화·Escape·포커스 제어와 명시적 복원, ARIA 탭·방향키 조작, EN/KR, GitHub 테마 변수, 좁은 화면을 지원합니다. 외부 데이터는 텍스트로 렌더링하며 HTML로 삽입하지 않습니다. 외부 폰트·스크립트·이미지는 필요하지 않습니다.
