# RepoDelta 1.0.3 검증 보고서

[English](QA.md) · [README](../README-KR.md)
**1.0.3 근본 원인 수정:** Chrome에서 일반 요청과 fallback 요청 모두 `TypeError: Failed to execute 'fetch' on 'WorkerGlobalScope': Illegal invocation`을 반환했습니다. 서비스 워커의 네이티브 `fetch` 함수를 `this.fetcher`에 저장한 뒤 인스턴스 메서드처럼 호출해 수신 객체가 서비스 워커 전역이 아니라 `GitHubClient`로 바뀐 것이 직접 원인이었습니다. 이 결함은 1.0.0-1.0.2에 동일하게 남아 있었습니다. 1.0.3은 fetch 의존성을 `globalThis`에 바인딩하고 수신 객체를 검사하는 회귀 테스트를 추가했습니다. 소스 패키지는 Node 94개와 오프라인 Chromium DOM 36개 검사를 통과했습니다. 현재 빌드 환경에서는 실제 GitHub API 네트워크 성공까지 검증할 수 없어 unpacked extension의 실제 요청은 사용자 환경의 최종 릴리스 게이트로 남습니다.

**1.0.1 회귀 수정:** 1.0.0을 실제 Chrome에 설치한 환경에서 토큰 유무와 무관하게 `NETWORK` 오류가 발생한 사례가 확인되었습니다. 1.0.1은 수동 리디렉션 전송 경로와 사용자 지정 `connect-src` CSP를 제거하고, RepoSize/RepoView에서 사용 중인 일반 Chrome `fetch` 흐름과 동일하게 `redirect: follow` 및 `cache: no-cache`를 사용합니다. 수정 후 Node 90개와 오프라인 Chromium 36개를 다시 통과했습니다. 실제 사용자 환경의 라이브 GitHub API 재검증은 업데이트 패키지 설치 후 확인이 필요합니다.

**상태: MVP 구현 및 자동화 테스트 통과. 네이티브 Chrome 설치와 실제 GitHub 연동은 배포 전 미완료 검증 항목입니다.** GitHub 저장소 생성·푸시와 Chrome 웹스토어 제출은 수행하지 않았습니다.

## 테스트가 확인한 범위

Node 94개는 URL·ref 검증, 응답 정규화 및 민감 필드 제거, 번역 키 일치, 백업 검증, 직렬 저장, 조회 스냅샷 연결, 화면에 표시된 SHA만 확인 완료, 오래된 탭 충돌, 빈 저장소, 슬래시 포함 브랜치, 브랜치·저장소 ID·이력 변경, 비교 불가와 한도 오류 구분, 커밋 페이지 처리와 500개 제한, 세션 전용 토큰, 인증 변경 무효화, 발신자 권한, 가져오기 원자성, ETag·304·TTL·중복 요청, 요청 헤더, API 허용 목록, 리디렉션, 쿨다운, 네트워크 오류를 포함합니다.

브라우저 36개는 실제 shared/background/content/options JavaScript를 모의 Chrome 어댑터로 실행했습니다. 단일 배지, 미등록 저장소의 자동 API 호출 없음, 명시적 추적 시작, 파일 표시·이전 파일명 검색, 삭제 파일의 이전 버전 링크, 커밋 탭·키보드, 어댑터의 언어 저장, 다크 테마, 390px 가로 넘침 없음, 새 HEAD가 생겨도 표시된 SHA만 확인, Escape·포커스 복원, 추가 커밋 조회 중 파일 목록 유지, 300개 파일 안내, 악성 파일명 텍스트 처리, 경고·취소, 한도 오류 재시도 반복 없음, 모의 페이지 이동, 플로팅 대체 버튼, 토큰 입력 초기화, 토큰 없는 백업, 전체 삭제 취소를 검증했습니다.

## 네이티브 검증을 완료하지 못한 이유

작업 환경의 Chromium에는 기업 관리 정책이 적용되어 있습니다. `dist/` 설치 시 `Loading of unpacked extensions is disabled by the administrator.` 오류가 발생했고, 로컬·GitHub 페이지 탐색도 관리자 URL 정책으로 차단되었습니다. 정책을 변경하거나 우회하지 않았습니다. 컨테이너의 인터넷 요청도 사용할 수 없어 확장에서 실제 GitHub API를 호출하는 스모크 테스트는 수행하지 못했습니다.

대신 `page.set_content`와 로컬 스크립트 주입으로 UI를 렌더링하고 GitHub API, 확장 메시지·저장소·탐색을 모의 처리했습니다. 이는 DOM과 해당 어댑터에서의 앱 동작을 확인한 것이며, 네이티브 MV3 API 검증이 아닙니다. QA 코드는 `qa/`에 격리하며 설치용 ZIP에는 포함하지 않습니다.

**미검증:** 네이티브 확장 설치, 서비스 워커 시작·정지·복원, 실제 `storage.session`의 브라우저 재시작 동작, 실제 GitHub DOM·SPA 탐색, 공개·비공개 저장소 API 인증과 조직 정책, 실제 브라우저 다운로드 완료, 웹스토어 심사, 원격 GitHub Actions, 다른 브라우저·GitHub Enterprise Server·모바일 설치.

화면 캡처에는 레이아웃 테스트용 페이지와 모의 데이터임을 표시했습니다. 실제 GitHub 통합 검증의 근거로 사용하지 말고, 배포 전 실제 환경에서 민감 정보를 제거한 화면을 다시 캡처하세요.

## 자동화 재실행

```sh
npm run package
```

npm 의존성 설치는 필요하지 않습니다. 브라우저 회귀를 재실행하려면 별도로 Python·Playwright·Chromium 실행 파일이 필요합니다. 이는 확장 실행 의존성이 아닌 QA 도구입니다.

```sh
python tests/browser_smoke.py
```

실행기의 기본 Chromium 경로는 `/usr/bin/chromium`입니다. 다른 환경에서는 `BROWSER_PATH` 환경 변수로 브라우저 실행 파일을 지정합니다. 이 테스트도 네이티브 확장 설치가 아닌 오프라인 하네스입니다. 정책 제한이 없는 브라우저에서 대화형 시뮬레이션은 다음과 같습니다.

```sh
npm run serve:qa
# http://127.0.0.1:5198/qa/index.html 열기
```

## 배포 전 실제 브라우저 확인

1. 관리 정책으로 막히지 않은 Chrome 프로필에 `dist/`를 로드합니다. 확장·워커 오류가 없는지, GitHub 새로고침 후 라이트·다크·dimmed 테마에서 버튼이 제대로 배치되는지 확인합니다.
2. 작은 테스트 저장소에서 기준점을 만든 뒤 외부에서 커밋을 추가하고 재방문합니다. 정확한 두 SHA의 GitHub 비교와 파일·줄 수·커밋 순서·삭제 파일 링크가 일치해야 합니다.
3. 비교 화면을 연 뒤 외부에서 커밋을 하나 더 추가하고 확인 완료합니다. 저장한 SHA는 화면에 원래 표시된 SHA여야 합니다. 두 탭을 열어 오래된 화면이 새 기준점을 덮어쓰지 못하는지도 확인합니다.
4. 실제 GitHub 소프트 탐색·뒤로/앞으로·탭 전환·헤더 재렌더링과 RepoSize·RepoView 등 동시 사용을 검증합니다. 중복 버튼, 깜박임, 이전 저장소 데이터가 남으면 안 됩니다.
5. 공개 저장소 비인증 조회, 테스트 비공개 저장소의 Contents 읽기 토큰, 잘못된·만료된·폐기된 토큰, 조직 승인을 확인합니다. 쿠키나 토큰이 API 외 요청에 누출되지 않아야 합니다.
6. 서비스 워커 정지·재시작, 확장 재로드·비활성화·다시 활성화, Chrome 재시작을 확인합니다. 기준점의 유지와 세션 토큰·캐시의 삭제, UI의 새 조회 요구가 실제 명세대로여야 합니다.
7. 실제 파일 다운로드로 백업하고 토큰이 없음을 확인한 후 가져옵니다. 기존 항목 유지·취소 동작도 검사합니다. 실제 민감 자료를 캡처에 사용하지 않습니다.
8. 현행 API·스토어 정책을 다시 검토하고 개인정보 처리방침의 공개 URL과 실제 문의 경로를 준비합니다. 라이브 화면을 캡처하고 권한·데이터 이용 신고를 검토한 뒤 최종 ZIP을 다시 설치해 확인합니다.

오프라인 테스트 통과는 위 배포 전 점검을 대체하지 않습니다.

## 1.0.3 근본 원인 감사

지속 오류의 원인은 토큰, CORS, 프록시, CSP, 리디렉션, GitHub API 자체가 아니었습니다. `GitHubClient`가 `constructor(store, fetcher = fetch)`로 서비스 워커의 네이티브 fetch 함수를 받은 뒤 `this.fetcher`에 저장했고, 실제 호출을 `this.fetcher(...)`로 수행했습니다. 이 호출 형태에서는 JavaScript 수신 객체가 `WorkerGlobalScope`가 아니라 `GitHubClient` 인스턴스가 됩니다. Chrome의 WebIDL 구현이 이를 검사하여 네트워크 I/O 전에 `TypeError: Illegal invocation`을 발생시켰습니다. 호환성 재시도도 같은 분리된 메서드를 다시 호출하므로 동일하게 실패했고, 설정의 연결 진단도 같은 전송 함수를 사용하여 같은 결함을 반복했습니다.

기존 Node 테스트는 `this`를 사용하지 않는 arrow/async fetch 스텁을 주입했고, 브라우저 QA 하네스도 확장 서비스 워커의 네이티브 fetch 대신 모의 fetch를 사용했습니다. 따라서 1.0.0-1.0.2는 실제 Chrome 전송 경로가 구조적으로 깨진 상태에서도 테스트가 통과할 수 있었습니다. 1.0.3은 fetch를 `globalThis`에 명시적으로 바인딩하고 수신 객체를 검사하는 회귀 테스트를 추가했습니다. 이 빌드 환경은 외부 연결이 제한되어 실제 GitHub API 성공 응답은 사용자 환경의 최종 릴리스 게이트로 남습니다.
